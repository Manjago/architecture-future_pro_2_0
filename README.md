# Task3Advanced — Проектирование целевой архитектуры и оценка рисков

## Задание

1. Спроектировать целевую архитектуру системы «Будущего 2.0» в горизонте трёх лет (C4, уровни контейнеров и компонентов)
2. Составить карту рисков трансформации (архитектурные, организационные, технологические)
3. Предложить план управления рисками

## Архитектурные решения и упрощения

### Доменная декомпозиция

Целевая архитектура разделена на следующие домены:

- **Медицинский домен** — управление пациентами, медицинские карты, диагностика
- **Финтех-домен** — биллинг, кредиты, платежи (банковская лицензия)
- **ИИ-домен** — ИИ-сервисы для медицинской диагностики и скоринга
- **Внутренний домен** — HR, инвентаризация, управление клиниками (упрощение: объединены в один домен, в реальном проекте могут быть разделены)
- **Аналитический домен** — Self-Service BI Portal («витрина данных»)
- **Платформа** — Event Bus (Kafka), Schema Registry, API Gateway, IAM
- **Legacy-мост** — DWH (SQL Server), Camel Bridge (на вывод к 36 месяцу)

### Осознанные упрощения

1. **Внутренние сервисы** (HR, инвентаризация, управление клиниками) объединены во «Внутренний домен». В реальном проекте при детальном проектировании каждый из них мог бы стать отдельным bounded context.

2. **Фармацевтические компании и производитель электроники** показаны как внешние системы (System_Ext) на Context-диаграмме. Детализация их интеграции — за рамками текущего задания, т.к. эти направления на этапе планирования (горизонт 3 года). При необходимости для каждого можно создать отдельную Container-диаграмму.

3. **Медицинские карты, истории болезни и результаты исследований** явно исключены из витрины данных (Self-Service BI Portal) — в соответствии с требованием бизнеса.

### Визуальные конвенции на диаграммах

- **Серый** (`legacy`) — компоненты на вывод (DWH, Camel Bridge)
- **Синий** (`new`) — новые компоненты целевой архитектуры
- **Оранжевый** (`bridge`) — временные мосты совместимости (ACL)
