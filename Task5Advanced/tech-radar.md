# Расширенный технологический радар «Будущее 2.0»

Технологический радар описывает целевой технологический ландшафт компании «Будущее 2.0» в горизонте трёх лет. Включает технологии, инструменты и архитектурные паттерны.

## Кольца

| Кольцо | Значение |
|--------|----------|
| **Adopt** | Стандарт для новых проектов. Команды используют без дополнительного согласования. |
| **Trial** | Применяется в пилотах и отдельных доменах. Осознанный выбор, готовность к рискам. |
| **Assess** | Изучаем, оцениваем потенциал. Прототипы и исследования, не для продакшена. |
| **Hold** | Не рекомендуется для новых проектов. Существующее использование поддерживается, план вывода определён. |

## Techniques — архитектурные паттерны и подходы

| Элемент | Кольцо | Обоснование |
|---------|--------|-------------|
| **Event-Driven Architecture** | Adopt | Центральный архитектурный принцип целевой платформы. Домены взаимодействуют через события (fire-and-forget, Avro). Обеспечивает слабую связность, near-real-time обработку и автономность доменов. |
| **Domain-Driven Design** | Adopt | Основа декомпозиции системы. 7 bounded contexts определены (Task4), агрегаты и контракты описаны. Все новые компоненты проектируются в терминах DDD. |
| **Infrastructure as Code** | Adopt | Вся инфраструктура описывается кодом (Terraform). Обеспечивает воспроизводимость, версионирование и аудит изменений. Обязательно для облачной миграции. |
| **Anti-Corruption Layer** | Adopt | Стандартный паттерн для интеграции с legacy. Camel Bridge реализует ACL между DWH/ESB и Event Bus. Обязателен на этапах 1–2 трансформации (0–18 мес.). |
| **Data Mesh** | Trial | Принципы доменного владения данными внедряются поэтапно: пилот в 1–2 доменах (0–6 мес.), масштабирование (6–18 мес.). Data products, каталог, governance — формируются по мере зрелости. Переход в Adopt после валидации на пилоте. |
| **Self-Service BI** | Trial | Портал самообслуживания спроектирован (Task3, component diagram). Реализация в рамках пилота. Переход в Adopt после запуска MVP и валидации бизнес-пользователями. |
| **CQRS** | Assess | Разделение моделей чтения и записи. Потенциально полезно для финтех-домена (высокая нагрузка на чтение отчётов, отдельная модель для записи транзакций). Требует оценки сложности внедрения. |
| **Event Sourcing** | Assess | Хранение состояния как последовательности событий. Потенциально полезно для финансовых операций (полный audit trail — требование регуляторов). Значительно усложняет модель данных, требует отдельного PoC. |
| **Batch ETL (централизованный)** | Hold | Текущий подход: данные из доменов стекаются в DWH пакетами, трансформируются хранимыми процедурами. Bottleneck по производительности (часы на отчёт) и по команде. Заменяется потоковой обработкой через Event Bus + Data Ingestion. |
| **Point-to-Point Integration (ESB)** | Hold | Apache Camel используется как point-to-point интеграция между системами. Тесная связность, O(N²) маршрутов при масштабировании, нет replay при сбоях. Заменяется событийной интеграцией через Kafka. Camel сохраняется только как bridge на переходный период. |

## Platforms — платформы и инфраструктура

| Элемент | Кольцо | Обоснование |
|---------|--------|-------------|
| **Apache Kafka** | Adopt | Event Bus — центральная инфраструктура целевой архитектуры. Распределённый лог, replay, мульти-DC репликация. Зрелая технология, широкое community. |
| **PostgreSQL** | Adopt | Основная СУБД для доменных сервисов (Medical DB, Fintech DB, Internal DB). Open-source, нет vendor lock-in, зрелая, managed-версии у всех облачных провайдеров. |
| **Kubernetes** | Adopt | Оркестрация контейнеров. Обеспечивает cloud-agnostic деплой, автоскейлинг, self-healing. Стандарт для всех новых сервисов. |
| **S3 / Object Storage** | Adopt | Хранение снимков, датасетов, артефактов моделей (AI Storage). Масштабируемое, дешёвое, стандартный API (S3-совместимый). |
| **ClickHouse** | Trial | Кандидат для Analytics Store. Колоночная СУБД, высокая производительность на аналитических запросах. Валидируется в пилоте аналитического домена. При неудовлетворительных результатах — альтернативы (Apache Druid, managed DWH облачного провайдера). |
| **Managed Cloud Services** | Trial | Managed Kafka, managed PostgreSQL, managed Kubernetes. Снижают операционную нагрузку, но создают зависимость от провайдера. Пилотируются на некритичных доменах, оценивается баланс удобства и lock-in. |
| **Microsoft SQL Server 2008** | Hold | End-of-life с 2019 года. Сотни ТБ данных, бизнес-логика в хранимых процедурах. План: поэтапная миграция данных в доменные БД (PostgreSQL) и Analytics Store, вывод к 36 мес. На переходный период — доступ через Camel Bridge (ACL). |

## Tools — инструменты

| Элемент | Кольцо | Обоснование |
|---------|--------|-------------|
| **Terraform** | Adopt | Infrastructure as Code. Cloud-agnostic, декларативный, модульный. Используется для всех окружений (dev/stage/prod). |
| **Keycloak** | Adopt | IAM: аутентификация, авторизация, SSO. Open-source, OIDC/SAML, интеграция с API Gateway. Единая точка управления доступом для всех доменов. |
| **Kong / Envoy** | Adopt | API Gateway: маршрутизация, rate limiting, аутентификация. Единая точка входа для внешних клиентов. |
| **Confluent Schema Registry** | Adopt | Каталог и валидация Avro-схем событий. Обеспечивает контрактную совместимость между продюсерами и консюмерами. Неотъемлемая часть Event Bus. |
| **Kafka Connect** | Adopt | Стандартные коннекторы для интеграции Kafka с внешними системами и хранилищами. Используется в Data Ingestion для загрузки проекций в Analytics Store. |
| **Grafana + Prometheus** | Adopt | Мониторинг и алертинг. Метрики инфраструктуры и приложений, дашборды, алерты. Open-source, де-факто стандарт для Kubernetes-кластеров. |
| **Apache Flink** | Trial | Потоковая обработка событий. Используется в Data Ingestion для сложных трансформаций (joins, windowing). Альтернатива — Kafka Streams (легче, но менее функционально). Валидируется в пилоте. |
| **MLflow** | Trial | Model Registry: версионирование и деплой ML-моделей. Используется в ИИ-домене. Альтернативы: Kubeflow, самописное решение. Пилотируется. |
| **Jaeger / Zipkin** | Trial | Distributed tracing. Сквозная трассировка запросов через домены (correlationId). Критично для отладки событийной архитектуры. Пилотируется вместе с первыми доменами. |
| **Power BI** | Hold | Текущая BI-система с кастомизациями поверх DWH. Тесно привязана к SQL Server. Заменяется Self-Service BI Portal (React + FastAPI + ClickHouse). Данные из Power BI мигрируются в новый портал поэтапно. |
| **PowerBuilder** | Hold | Клиентский интерфейс оператора. Legacy-технология, разработка и поддержка дорогая, специалисты дефицитны. Заменяется React-based Web UI через API Gateway. Вывод к 36 мес. |

## Languages & Frameworks — языки и фреймворки

| Элемент | Кольцо | Обоснование |
|---------|--------|-------------|
| **Java / Kotlin + Spring Boot** | Adopt | Основной стек для медицинского, кредитного и внутреннего доменов. Зрелая экосистема, широкий пул специалистов, отличная поддержка Kafka и gRPC. |
| **Python + FastAPI** | Adopt | Стек для ИИ-домена и компонентов BI Portal (Report Builder, Query Engine, Data Catalog, Access Control). Быстрая разработка, богатая ML-экосистема. |
| **Go** | Adopt | Стек для финтех-сервисов (Billing Service). Высокая производительность, низкое потребление ресурсов, простота деплоя. |
| **React** | Adopt | Фронтенд для Self-Service BI Portal (Web UI) и нового интерфейса оператора. SPA, богатая экосистема компонентов, широкий пул специалистов. |
| **PowerBuilder (язык)** | Hold | Legacy-язык клиентского интерфейса. Специалисты дефицитны и дороги. Новая разработка на PowerBuilder запрещена. Существующий интерфейс поддерживается до вывода (36 мес.). |
